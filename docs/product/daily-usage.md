# 每日使用流程（owner 手册）

> 目标：把「订阅式个人练习」跑成每天 10–20 分钟的稳定循环。所有数字都是**观察值**，不是能力值，更不是中考分数预测。

## 1. 每日循环（约 10–20 分钟）

1. **首页**：看「目标与学习计划」——每个知识点的状态（证据不足 / 知识点差距 / 未确认短板）与建议动作；看「题库体检」确认还有没有足够的未见题可诊断（余量为 0 时先复练或在审核台补题）。
2. **阶段诊断**（优先）：领取未见题 → 独立作答（不看资料、不查工具）。提交后计划与阶段对比自动刷新。
3. **专项训练 · 复练**：按首页建议的知识点练习；做过的题会轮换出现，连续取题即可见不同题。
4. 主观题（解答/论述）：提交后对照参考答案**自评**——自评是独立来源记录，只作溯源对照，不进客观证据。

## 2. 导入一套新卷子（真题或学校卷）

1. **审核台 → 题源台账**：新建题源（标题、科目、版权状态）。
2. **来源人工审核**：填年份、https 来源链接、获取日期、版权依据、适用性说明，勾选"我已人工核查"。这是人工门禁：未审核的题源无法发布题目。
3. **附件与解析**：上传原始 PDF/图片（扫描 PDF 会自动走逐页 OCR 草稿）→ 点「解析」。解析文本（含页码标记）只是**录入对照草稿**，OCR 可能错字，绝不自动成题。
4. **逐题录入并确认导入**：对照草稿人工誑写题干/选项/答案/知识点/满分，勾选"我已逐题人工核对"后确认导入。题干可写公式：`$…$` 行内、`$$…$$` 独立块（KaTeX 渲染）。
5. **题目草稿与发布**：逐题人工审核通过 → 发布（发布仍要求来源已人工审核且版权状态已核实）。
6. 学校考试后：进入**管理端 → 学校考试**，在「新建校考档案」录入考试总分，或先取消勾选人工核对以**暂存待核对档案**、在「原卷与答题卡」上传学校原卷与学生答题卡（私有隔离保存，不进入公共题库），待成绩公布后再回到「总分台账与核对」补充实得总分并确认锁定（总分仅记录，不折算考点证据；逐题核对的得分才产生证据）。
7. **学校考试错误分析与复盘**：第三阶段「已核对明细与补录」仅负责分值与考点确认；所有复盘功能均集中在第四阶段「**错误分析与复盘**」（含本场失分概览与错因分布、失分考点与日常练习交叉诊断、历次顽固失分点对比，以及第 4 步「**失分题干与学生复盘**」：按需提取并确认原题题干与学生作答，逐题仅 AI 识别一次、确认后同步至学生端「校考复盘」，并支持只读查看学生复盘、书童对话过程与退回重写留言）；学生端支持「三步引导卡片」与「书童陪你想」双轨切换（聊满 2 轮可整理草稿回填三步卡，由学生修改后确认提交）；道法等未设独立刷题考点体系的科目诚实呈现「档案复盘」，不虚构练习交叉诊断或成绩预测。

## 3. 边界（必须了解，避免误读数据）

- **未见题纪律**：领了未见题就要独立完成；刷新/重开不会丢题（自动恢复），但领而不答仍占用一次曝光。
- **证据不足就显示不足**：从不显示 0 分冒充不会，也绝不把"题少"推断成"弱"。
- **自评与自动判分并列可溯源**：自评不可修改、只记一次。
- **学校总分 ≠ 知识点能力**：只有逐题人工核对的得分才进入画像。
- 里程碑/阈值是**未校准**的规划假设；阶段对比只是小样本可观察对比。

## 4. 常用运维（本地常驻栈）

```bash
infra/deploy.sh            # 部署当前 HEAD（构建→迁移→替换 api→冒烟）
infra/deploy.sh --web      # 同前并重建 Web 产物
infra/rollback.sh          # 回滚到上一个可用镜像标签
```

备份每 4 小时自动执行（R2 异地 + healthchecks.io 静默告警）；恢复流程见 [recovery-runbook.md](../operations/recovery-runbook.md)。iPad 真机核对清单见 [ipad-field-checklist.md](../operations/ipad-field-checklist.md)。前端重构与人工验收步骤见 [manual-acceptance.md](../quality/manual-acceptance.md)。

## iPad 使用注意（2026-10-30 实测）

- **主屏幕 PWA 与 Safari 是两套独立存储**：在 Safari 里勾选"在本机记住令牌"对主屏幕图标启动的应用不生效。日常走主屏幕图标的话，请在 PWA 内勾选一次即可长期免输入。

## 校考 M2 逐题草稿自动解析与错误分析

- 在管理端 **「学校考试」→「原卷与答题卡」** 上传 PDF / DOCX / PNG / JPG 后，可直接点击 **「前往解析 M2 草稿」** 进入 **「逐题得分与考点」** Tab。
- **双模式草稿抽取**（所有结果强制落库为 `ocr_draft` 且 `confirmed_by_user=False`，人工确认前绝不进入能力画像或错误分析）：
  - **纯文字卷本地骨架模式**（`skeleton_only`）：零外网调用，直接从文字层抽取题号、分值与 Top-3 候选课标考点。
  - **DeepSeek 多模态联合识别**（`auto`）：配置 `DEEPSEEK_API_KEY`（或 `SHUTONG_AI_API_KEY` / `SHUTONG_VISION_API_KEY`）后使用视觉/文本模型联合查看原卷与答题卡；默认对答题卡首页顶部 `24%` 学生姓名/考号区域本地遮白脱敏后再送检。
- 在 **「OCR / 同步草稿校对台」** 可逐题修正得分、满分、点选候选考点、标注错因分类与复盘备注，支持单题 **「确认入账」**、**「丢弃草稿」** 及 **「批量确认本页已核对草稿」**；确认后即时刷新 **「错误分析与复盘」** Tab（错因占比、与日常练习掌握度交叉诊断、跨场次顽固失分追踪）。

## 外部校考平台（k12100.com）与 DEEPSEEK_API_KEY 命令行安全配置

本能力运行在宿主机，**所有账号密码、`DEEPSEEK_API_KEY` 与浏览器状态均按环境隔离存放在仓库之外的 `$PAGEBOY_HOME/<development|production>/k12100/`**（目录 `0700`、文件 `0600`）与 `$PAGEBOY_HOME/development/env/dev.env`（`0600`）或 `$PAGEBOY_HOME/production/env/prod.env`（`0600`），严禁写入 Git，也不在终端回显明文（不再使用全局 `~/.config/shutong/`）：

1. **安全初始化 k12100 凭据（可选同步录入 DeepSeek Key，权限自动锁定 `0600`）**：
   - 交互录入（推荐，密码与 Key 均不回显）：`uv run python scripts/k12100_sync.py init-credentials --env development`
   - 仅从当前 Shell 安全持久化 `DEEPSEEK_API_KEY` 并同步写入开发环境 `dev.env`（不覆盖既有 `k12100` 账号或开发令牌）：
     - `uv run python scripts/k12100_sync.py config-deepseek --env development --from-shell --sync-dev-env`
   - 若仅配置日常开发环境（`8000` 端口）的 DeepSeek Key：
     - `uv run python scripts/run_dev_env.py config-ai --from-shell`（或省略 `--from-shell` 进行无回显交互输入；支持 `--clear` 清理）
2. **检查凭据权限、DeepSeek Key 脱敏摘要与已同步台账**：
   - `uv run python scripts/k12100_sync.py status --env development`
   - `uv run python scripts/run_dev_env.py status`
3. **人工测试与日常开发环境启动**：
   - `uv run python scripts/run_dev_env.py start` 会按权限校验顺序自动加载 `DEEPSEEK_API_KEY` / `SHUTONG_AI_API_KEY`；不自动灌入虚构测试数据。
4. **可见窗口探测（首日推荐）**（打开宿主机 Chromium，登录后手动浏览 1~2 场考试，在 `$PAGEBOY_HOME/<env>/k12100/probe_snapshot/` 生成脱敏页面/XHR 快照）：
   - `uv run python scripts/k12100_sync.py probe --env development`
5. **增量去重同步为 M2 待核对草稿**（默认对接本机回环测试端 `http://127.0.0.1:8000`，生产环境可通过 `--env production` 与 `--api-url http://127.0.0.1:8180` 指定）：
   - `uv run python scripts/k12100_sync.py sync --env development --api-url http://127.0.0.1:8000 --max-exams 2`
   - 若遇验证码、滑块或 HTTP `401/403/429`，脚本会立即熔断停止并发出提示，绝不自动重试或绕过校验；同步后仍需家长在管理端 **「草稿校对台」** 人工核对确认。
6. **管理端「从 k12100 补全各科」与全科离线采集包导入**：
   - 在管理端 **「学校考试」** 顶栏点击 **「从 k12100 补全各科」**，系统自动识别运行环境：宿主机就绪时可直接一键启动单任务后台全科补全；容器化或隔离环境自动切换为通用离线采集包导入（支持上传 `15 MiB` 内脱敏 JSON，服务端强制执行 PII 递归清洗、JPEG 答题卡校验、已有原卷 PDF 提干，并严格将全部逐题草稿标为 `ocr_draft` 待人工确认）。
   - 宿主机配套命令行导出与一站式导入命令：
     - 导出 `0600` 脱敏采集包：`uv run python scripts/k12100_sync.py collect --env development`
     - 一站式或离线包导入：`uv run python scripts/k12100_sync.py backfill --env development`（支持 `--input-json` 离线包与 `--dry-run` 预演）

## 校考试卷自动发现与四步同步中心（ST-EXAM-AUTOSYNC-01）

管理端 **「学校考试」→「全科校考同步」** 现在是四个步骤，而不是一组并列参数：

1. **发现试卷**：顶栏显示当前环境与 `$PAGEBOY_HOME/<env>/school-exams/inbox` 私有目录。把合法取得的 PDF / DOCX / PNG / JPG 放入该目录后点 **「扫描私有收件箱」**；也可在宿主机用 `python scripts/school_exam_pipeline.py scan --source-dir <已授权目录>` 把文件复制进私有 inbox 后扫描。**未配置真实授权卷源时会明确显示 `SOURCE_NOT_CONFIGURED`，不会伪造远程下载。**
2. **匹配考试**：R2 只以五项核心字段筛选：**学年度、年级、考试类型、学科、考试日期**。学校、学期、考试系列不识别，也不参与匹配。卷头 OCR 会检查前两页完整区域，包括右下方小字日期；完整日期保存为 `2026-10-12`，原卷只有 `2026.10` 时保存 `2026-10`，不补 01 日。多个同月“统一练习”候选会返回歧义，需用平台考试 ID/全称或人工确认。类型“统一练习”不会被改写成月考/期中。
3. **k12100 报告同步**：无需先选试卷即可打开。点击 **「从 k12100 下载总分报告并同步」** 后，系统读取 k12100 首页列表获取考试时间与场次 ID，自动跳过已有报告的场次，每次最多串行进入 3 场「总分 → 报告打印 → 下载PDF」下载分析报告册。后端解析学年度、年级、类型、学科与成绩后，对未建档科目按平台日期新建待核对 `SchoolExam` 档案，对未锁定档案更新总分并补全空身份字段，更新未确认的逐题 `ocr_draft` 得分并同步答题卡附件；已人工锁定总分或非空身份冲突仅标红提示而不覆盖。完成后可返回第 2 步把本地试卷精确匹配到新档案，或直达第 4 步核对锁定总分。仍支持在「高级设置与离线包」中上传离线 JSON 采集包。
4. **核对入档**：先查看总分、逐题草稿、私有附件与本人排名。勾选人工核对后才能锁定总分；排名只有通过本人归属校验后才能入档，并单独确认来源，不进入能力画像。逐题草稿仍需到「原卷与草稿校对」逐题确认，未确认的草稿不会进入错误分析。错误分析入口保留在该场考试原有 Tab。

CLI 的 `--dry-run` 严格只读；`run` 只对唯一精确匹配的原卷自动做私有入档，不自动确认总分。真实学校卷源、真实 k12100 连接及真实排名可用性目前为 `BLOCKED / NOT_VERIFIED`：请把合法取得的文件放入 inbox，或使用平台导出的离线采集包；不要把北京市中考真题库当作学校月考/期中/期末卷源。

详细技术边界见 [校考试卷自动发现与严格匹配](../engineering/school-exam-autosync.md)。

## 校考分析报告册导入与核对（报告导入与核对 Tab）

管理端 **「学校考试」→「报告导入与核对」** 与「全科校考同步」并存，面向多学科分析报告册 PDF：

1. **扫描与识别**：从当前环境私有收件箱识别分析报告册（单科扫描入口会自动跳过分析报告册，避免误当单科试卷建档）；可人工补录缺失学年度/年级/类型或补录缺失学科成绩。
2. **场次关联与核对**：按场次匹配同届校考档案，人工确认后可把未锁定的各科总分回写台账，并生成逐题 `ocr_draft` 草稿及本地/AI 知识点候选（须到「原卷与草稿校对」人工确认后才进能力画像）。
3. **答题卡切片**：可按报告页码渲染私有答题卡 PNG、调整旋转方向并同步至关联场次附件，仅经管理员私有鉴权接口查看。
