# 双画像、差距分析、自适应训练与独立验证

## 六段业务闭环

目标（科目分数、考试基线、时间预算）→ 候选目标画像 → 练习/校卷/独立测评形成现实画像 → 差距/证据缺口 → 专项训练步骤 → 未见题独立评估 → 重新规划。

两类画像必须遵守统一评价口径；学校月考与北京中考并非当然等值。未经过考试蓝图和校准样本支撑，不得把目标分数反推成精确知识点阈值。候选目标要求应显式标记假设。

## 当前可执行启发式（ST-005 后）

`services/api/shutong/guidance.py` 是纯函数，输入独立、首曝、客观已评分且只有一个主考点的 Evidence；至少3道独立题后才给出观察比例。少于3题返回证据不足。按科目目标比例使用0.7/0.8/0.9三个**未校准的规划代理阈值**，主要用于演示规则决策，绝不是考试能力或预测分数。

### 独立复测可观察对比（ST-005）

`compare_validation`（纯函数）与 `GET /api/guidance/validation` 把上述证据按时间切成基线诊断与复测两侧：每个知识点前 3 条去重条目为基线，其后为复测。知识点两侧均 ≥3 条才可比；不足一侧即 `cannot_compare`（先查基线侧）；无可比知识点时总判决 `CANNOT_COMPARE`。可比知识点按条目满分加权的合并观察率比较，只给 `improved / no_improvement` 的**小样本可观察对比**（相等不宣称 improved），总判决为 `IMPROVED_ON_COMPARABLE_SCOPE / NO_OBSERVED_IMPROVEMENT`，永不输出分数预测或跨考试等值结论；不可比范围一律不宣称涨分。纯度由 AST 导入白名单（仅 `__future__/dataclasses/collections/typing`）与禁用符号扫描静态锁定（更换 OCR/解析实现无法影响它）；历史 `AnswerAttempt` 不可变，规则调整只影响纯派生输出（回放测试锁定）。

如果题目早已曝光，只能作为复练，不能标记新题验证。复测还需检查题型、难度与评分可比性；当前骨架已实现"是否曾曝光"与"独立/无提示/单考点/客观评分"的证据纪律和第一阶段可观察对比，**并未完成正式的独立效果推断**。

### 题池体检（ST-015）

`pool_health`（纯函数）与 `GET /api/guidance/pool-health` 按逻辑题的最新已发布版与学习者曝光记录如实计数：每知识点的已发布题数、未见题存量（诊断余量）、已曝光数；题目总数按逻辑题去重（修订新版本不重复计数），`evaluation_available` 只反映"是否还有未曝光已发布题"。它只回答"题库够不够支撑训练与诊断"，不制造分数、不推断知识点重要性（题少可能只是尚未导入）。

## 需要后续实现

- 学校试卷上传、逐题人工核对、评分点证据；多来源可信度等级。
- 目标画像基于已审核考试蓝图生成多候选路径、标明无法覆盖的听说和实验。
- 有真实题库覆盖支持的知识点、难度与前置依赖，预计投入成本与训练效益。
- 计划快照、可解释依据、重算版本和阶段级触发，避免每做一道题计划震荡。
- 限时条件与真正可比未见题复测，样本不足显示“无法判断”，并检验跨时间保持。
