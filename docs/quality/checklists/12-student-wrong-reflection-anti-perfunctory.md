> **归档位置**：`docs/quality/checklists/12-student-wrong-reflection-anti-perfunctory.md`  
> **总控索引**：[manual-acceptance.md](../manual-acceptance.md)  
> **前置依赖**：宿主机仅回环测试服务（`127.0.0.1:8000` + `127.0.0.1:5173`）已通过 `uv run python scripts/run_dev_env.py start` 启动，且管理端已存在至少 1 条已确认的校考失分题（未确认或满分题不会进入学生端复盘队列）。  
> **中断协议**：若出现学生端泄露内部 `knowledge_id` 编码、填写“粗心/不会/下次注意”或重复刷屏仍能提交成功、管理端核对台仍可代填错因与复盘备注、或学生端新增视图存在横向溢出/遮挡，请立即勾选「暂时中断核验，先修理Bug」。

## 一、 测试环境与访问入口

- **管理端入口**：`http://127.0.0.1:5173/admin.html` → **「学校考试」** → **「原卷与明细核对 / 已核对明细与补录」**
- **学生端入口**：`http://127.0.0.1:5173/` → 顶部导航 **「错题复盘」**
- **模拟机调出命令**：
  - 竖屏（`810 × 1080`）：`uv run python scripts/run_dev_env.py sim`
  - 横屏（`1080 × 810`）：`uv run python scripts/run_dev_env.py sim-landscape`

## 二、 逐项核验清单

- [x] **12.1 · 管理端边界收敛（仅确认分值与知识点，不代填复盘）**：打开 `admin.html` → 「学校考试」→「逐题明细核对台」与「人工补录已核对小题」，确认已移除「错因分类」与「错题复盘备注」输入框；失分题仅显示「确认入账后将推送至学生端」提示，且不影响原「满分题无需复盘」展示。
- [x] **12.2 · 学生端「错题复盘」视图与数据隔离**：进入学生端 `http://127.0.0.1:5173/`，确认顶部导航出现 **「错题复盘」**（有待复盘题时显示红色待复盘数量徽标），支持 5 门学科切换与状态筛选；核对卡片上只展示自然语言考点名称（绝不出现 `math_cand.*` 等内部编码）与失分详情，且在 iPad 竖横屏下无横向溢出。
- [x] **12.3 · 三层防敷衍质检拦截**：选择任一待复盘失分题，尝试输入 `"太粗心了没看清"` / `"下次一定注意认真审题"` 或 `"11111111111"` 等连续重复字符后点击「提交高质量复盘」，确认系统当场拦截并弹出明确引导提示（未通过则不保存）；若配置了 DeepSeek Key 且输入笼统内容，可观察到 AI 老师追问提示。
- [x] **12.4 · 实质复盘提交 → 管理端只读查看 → 退回重写闭环**：在「具体失分卡点」和「正确思路与改进对策」分别填入具体解题步骤与可执行检查动作后提交，确认状态变为「已完成复盘 ✓」；随后切回管理端「已核对逐题明细」与「错误分析与复盘」，确认可只读看到学生所选错因与双栏复盘并计入错因分布；点击「退回重写」填写原因后，切回学生端确认该题重回待复盘并显示退回要求横幅。
- [x] **12.5 · 精简标题与按校考台账场次独立分组**：确认学生端工作台主标题已精简为 **「校考错题复盘」** 且无多余副标题；同科存在多场校考时，按校考台账名称与日期分块呈现，不将不同考试的题目混排在同一列表。
- [x] **12.6 · 去“防敷衍”说明 & 方案一（台账目录 → 单场专注页）**：确认学生端界面已完全移除“防敷衍”提示说明；首屏仅展示校考台账卡片目录，点击某场「进入本场复盘 →」后进入该场专属复盘页，点击「← 返回校考台账」可返回目录（后台仍正常拦截套话/刷屏）。
